# k7x: the text format

`packages/k7x` is the parser, printer and editor for `.k7x` files: the same data as a workspace's
YAML files, in a Strudel-looking syntax that is **parsed and never evaluated**. A call is a map entry,
a chain of calls is a map, and nothing computes. It has no `node:` import, so the browser editor uses
it directly. The user-facing syntax is in the user guide's song file reference.

## Modules

| Export | File | Role |
|---|---|---|
| `@studio/k7x/ast` | `packages/k7x/src/ast.ts` | The tree: scalar, list (`brackets` or call `args`), map (`root`, `chain`, `object`), every node with its source span. `toJS` gives exactly what YAML's `toJS` would, `nodeAt` walks a key path. |
| `@studio/k7x/parse` | `packages/k7x/src/parse.ts` | `parseTree(text)` → the root map; throws `K7SyntaxError` with offset, line, column. Duplicate keys are syntax errors. |
| — (inside the package) | `packages/k7x/src/print.ts` | The one canonical layout (100 columns) for text written whole: maps in a list print as chains, multi-line strings as backtick strings. |
| `@studio/k7x/document` | `packages/k7x/src/edit.ts` | `K7Document`: `getIn`, `hasIn`, `setIn`, `addIn`, `insertIn`, `deleteIn`, `replaceSource` by key path, rewriting only the edited value's span; `parse(text)` for plain data. |
| `@studio/k7x/from-yaml` | `packages/k7x/src/fromYaml.ts` | YAML text → k7x text, carrying comments and blank lines; refuses anchors, tags and non-map roots. A flow collection stays on one line. |
| `@studio/k7x/yaml-bridge` | `packages/k7x/src/yamlBridge.ts` | `toYaml(k7x, sugar)` and `applyYaml(k7x, yaml, sugar)`: let code that speaks YAML read and write a k7x file. |

## The bridge: why nothing else had to change

Every reader and writer in `@studio/song` and `@studio/song-edit` speaks YAML text. Rather than
teach each of them a second format, `packages/song/src/yaml/workspaceFile.ts` sits in front of the
disk:

- `realPath(path)`: a YAML-named path resolves to its `.k7x` sibling when that exists, so `x.k7x`
  wins over `x.yaml`.
- `wsRead(path)`: a `.k7x` file is returned as YAML text (`toYaml`), short forms expanded.
- `wsWrite(path, yaml)`: on a `.k7x` file, the new YAML is compared with the file's current data and
  the difference applied as path edits (`applyData`: changed leaves, added and removed keys, list
  splices with common head and tail kept). The file's comments and layout survive.
- `wsList(dir)`: lists `.k7x` files under their YAML name, so a `.yaml` filter keeps finding them.
- `wsRename`, `wsCopy`, `wsRemove`, `wsIssues` keep the format of whatever is on disk.

A writer's output is therefore identical whether the file is YAML or k7x, and the k7x side is tested
against the same corpus.

**Short forms** (`packages/song-schema/src/yaml/sugar.ts`) are part of the bridge: `notes("c4 e4")`
or `notes(seq("…").step(0.5).v(0.8))` in a sequence, and `runs([[a, b, c]])` in a graph. `sugarFor(path)`
returns the expansion for a path's kind. On write, a short form whose expansion is unchanged stays
as written; one whose expansion changed is replaced by its full data, or a stale short form would
undo the edit.

## The deploy switch: `STUDIO_K7X`

| Value | Effect |
|---|---|
| unset | k7x files are read everywhere; new files are created as YAML. |
| `1` | New files are created as `.k7x` when the text converts to the same data. `POST /migrate-k7x` may convert a workspace. |
| `only` | YAML is no longer read by any lookup or listing; a new file is k7x or the write fails. |

The switch exists because every device that opens a workspace — desktop builds and phones included —
must read k7x before any file is written as one. It is read in `k7xMode()` in
`packages/song/src/yaml/workspaceFile.ts`.

## Migration

`migrateToK7x(root, { backup, dryRun, skip })` in `packages/song/src/k7xMigrate.ts` converts each YAML
file only when the k7x text reads back to the same data (`convertChecked`); otherwise the file stays
YAML and is reported with its reason. A YAML file already shadowed by a `.k7x` sibling is left alone.
Converted originals go to the hidden `.k7x-backup/` folder. Two files stay YAML by name because code
outside the bridge reads and writes them atomically: `_library-pins.yaml` and a library's
`library.yaml`.

Ways to run it:

- `npx tsx packages/song/scripts/migrateK7x.ts <dir> [more dirs…] [--write] [--backup <dir>]` — dry
  by default.
- `POST /migrate-k7x` `{ dryRun? }` on a file service, refused unless `STUDIO_K7X` is set.

## Validation and the editor

`validateFile` routes a `.k7x` path through `k7xSyntaxIssue`, then the kind's YAML parser on the YAML
view (`checkK7x` in `packages/song-schema/src/yaml/k7xIssues.ts`). Findings are relocated onto the k7x
text by their key path (`locateK7x`), never by line number, since the YAML view's lines are unrelated.
The CodeMirror language, cursor model and completions are in `packages/ui-editor/src/k7x/`.
