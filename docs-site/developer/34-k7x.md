# k7x: the text format

`packages/k7x` is the parser, printer and editor for `.k7x` files, the only format a workspace's
documents are written in: a Strudel-looking syntax that is **parsed and never evaluated**. A call is
a map entry, a chain of calls is a map, and nothing computes. It has no `node:` import, so the
browser editor uses it directly. The user-facing syntax is in the user guide's song file reference.

## Modules

| Export | File | Role |
|---|---|---|
| `@studio/k7x/ast` | `packages/k7x/src/ast.ts` | The tree: scalar, list (`brackets` or call `args`), map (`root`, `chain`, `object`), every node with its source span. `walk` visits it, `nodeAt` walks a key path. |
| `@studio/k7x/parse` | `packages/k7x/src/parse.ts` | `parseTree(text)` → the root map; throws `K7SyntaxError` with offset, line, column. Duplicate keys are syntax errors. |
| `@studio/k7x/print` | `packages/k7x/src/print.ts` | `stringify(value, { header, inline })`: the one canonical layout (100 columns) for a file written whole, with `//` header lines and the nodes kept on one line. |
| `@studio/k7x/document` | `packages/k7x/src/edit.ts` | `K7Document` and its `K7Scope`: `getIn`, `hasIn`, `setIn`, `addIn`, `insertIn`, `deleteIn` by key path, rewriting only the edited value's span; `parse(text)` for plain data. |
| `@studio/k7x/sugared` | `packages/k7x/src/sugared.ts` | New data applied over a document that holds short forms, each kept while its expansion is unchanged. |
| `@studio/k7x/native` | `packages/k7x/src/native.ts` | The Rust reader where the runtime has one; it only ever answers what `parse.ts` would. |

## Where a workspace reads and writes them

`packages/song/src/yaml/workspaceDoc.ts` is the door: a file's text (`wsText`), its data with short
forms expanded (`wsData`), an edit by key path (`wsEdit`), or a whole file from data (`wsWriteData`).
A writer takes a `K7Scope` and edits the document in place, so a knob drag stays a one-line diff and
every comment survives. `packages/song/docs/k7xFiles.md` holds the rules.

**Short forms** (`packages/song-schema/src/yaml/sugar.ts`): `notes("c4 e4")` or
`notes(seq("…").step(0.5).v(0.8))` in a sequence, and `runs([[a, b, c]])` in a graph. `sugarFor(path)`
returns the expansion for a path's kind. On write, a short form whose expansion is unchanged stays
as written; one whose expansion changed is replaced by its full data, or a stale short form would
undo the edit.

What stays YAML is no workspace document: the media library's store on its volume, `env.yaml`,
`commands.yaml`, `latest.yml` and the machine's `preferences.yaml`. A save of a `.yaml` path through
the file service is refused.

## Validation and the editor

`validateFile` reads a `.k7x` path with the kind's parser; a syntax error is one finding with its
line and column (`packages/song-schema/src/yaml/k7xIssues.ts`), and a schema finding is placed on
the text by its key path (`packages/song-schema/src/yaml/k7xPosition.ts`). The CodeMirror language,
cursor model and completions are in `packages/ui-editor/src/k7x/`.
