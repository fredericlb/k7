# CI

Two CI systems run on this repository:

- **GitHub Actions** (`.github/workflows/`): the checks for the k7 side (`k7.yml`), the production
  Docker images on GHCR (`images.yml`), and the desktop release for all three desktops plus Android.
- **OneDev** (`.onedev-buildspec.yml`): the full lint and test run, Docker images in OneDev's own
  registry, and a Windows and Android release graph of its own. No OneDev job has a trigger: they
  run by hand, and nothing deploys what they push.

Both check out the private `commons` submodule at the commit this repository pins. On GitHub that
is a second `actions/checkout` of `fredericlb/commons` at `git rev-parse HEAD:commons`, using the
`COMMONS_TOKEN` secret (falling back to the workflow token); on OneDev it is the
`submodule-token` secret.

## GitHub: the `k7` workflow

`.github/workflows/k7.yml` runs on every push to `main`, every `v*.*.*` tag, every pull request and
on manual dispatch, with no path filter: it is the gate the image and desktop publishes wait for
(`.github/actions/k7-passed`), and a publish whose commit has no green `k7` push run fails. A newer
push to a branch cancels its running one; on `main` and on tags every commit's run completes.

| Job (name) | Gates? | Steps |
|---|---|---|
| `js` (`tests + typecheck`) | Yes | `npm run test --workspace=apps/k7 --workspace=packages --if-present`; `npm run build` on the same workspaces (a `tsc --noEmit` per package, a real `vite build` plus typecheck for the frontend); `tsc --noEmit` in `apps/k7/backend` and in `packages/rehearsal-server`, which have no `build` script. |
| `supervisor` (`supervisor (native)`) | Yes | Installs Ninja, builds `engine/k7-supervisor` with the `dev-gcc` preset, runs `k7_supervisor_tests`, then runs `packages/engine-tunnel`'s Vitest suites against the built `tunnel_harness` as well as the TypeScript agent. |
| `lint` (`lint`) | Yes | `npm run lint` (Biome over the whole tree: errors fail, warnings do not) and `npm run lint:bytes`. |

No job compiles the C++ engine: that only happens in the desktop release. The workflow's file name
and the gating job names are what branch protection matches on, so renaming them needs the
branch protection setting changed with it.

The jobs' scope is deliberately the k7 side of the repository; widening one is one more
`--workspace` in its command.

### The shared `node` action

`.github/actions/node/action.yml` sets up Node from `.nvmrc` and restores every `node_modules`
folder (root, `apps/*`, `apps/k7/*`, `packages/*`, `engine/*`, `engine/k7-android/*`, `commons/*/*`)
from a cache keyed on the OS, architecture, `.nvmrc` and `package-lock.json`. Only an exact key is
accepted; on a miss it runs `npm ci`. It needs the repository and `commons` checked out first.

## GitHub: the desktop release

`.github/workflows/desktop.yml` and `.github/workflows/desktop-platform.yml` build what ships to a
musician's machine. See [Releases and publishing](./09-releases-and-publishing.md) for what they
produce; this is the job graph.

Triggers: pushes to `main`, tags matching `v*.*.*`, manual dispatch. A newer run on the same ref
cancels the older one.

| Job | Runs on | Does |
|---|---|---|
| `decide` | Ubuntu | Picks the channel (`release` for a tag, `snapshot` otherwise), the tag (`snapshot` or the tag name) and the stamp (the tag, or `snapshot-<short sha>`). For a push to `main` it diffs against the previous commit and skips the build unless something under `engine/`, `apps/`, `packages/`, `commons`, `package-lock.json` or the two workflow files changed (a `paths:` filter cannot be used because it also applies to tag pushes, which carry no commit list). Publishes only for a tag or for `main`; a dispatch on another branch builds without publishing. |
| `build` (matrix, calls `desktop-platform.yml`) | `windows-latest` (preset `windows-msvc-ninja`), `macos-latest` arm64 (`macos-clang`), `ubuntu-latest` (`release-gcc`) | Per platform, an `engine` job then a `desktop` job. `fail-fast` is off, so one platform's failure does not cancel the others. |
| `android` | Ubuntu | JDK 21, Android SDK platform 36, build-tools 36.0.0, NDK 29.0.14206865; `./gradlew --no-daemon assembleDebug` in `engine/k7-android`; uploads `k7-android_<stamp>_arm64.apk`. |
| `tested` | Ubuntu | Only when the run publishes: waits for `k7.yml`'s push run on the same commit and ref, and fails if it failed or never ran. |
| `publish` | Ubuntu | Needs `tested`. Downloads every artifact into one folder and creates the GitHub release with `gh`. |

### `desktop-platform.yml`

**`engine` job** (per platform):

1. Installs build dependencies: on Linux, Ninja and the JUCE dependencies (ALSA, JACK, X11, fonts,
   curl, LADSPA); on macOS, `cmake` and `ninja` from Homebrew if missing; on Windows, the MSVC
   developer environment, plus Defender exclusions for the workspace and compiler processes.
2. On non-Windows runners, sets `CMAKE_BUILD_PARALLEL_LEVEL` to every core (the build script
   otherwise leaves two free).
3. Restores the dependency sources cache (Windows only) and an sccache compiler cache (2 GB, per
   platform; failure to set it up is not fatal).
4. Runs `node engine/scripts/build-engine.mjs` with `STUDIO_ENGINE_PRESET`,
   `STUDIO_SUPERVISOR_PRESET`, `STUDIO_FETCHCONTENT_DIR` and `STUDIO_COMPILER_LAUNCHER` set.
5. Strips build output from the fetch folder so only sources are cached.
6. Runs `node engine/scripts/package-release.mjs --kind engine --stamp <stamp>` and uploads the
   archive (an archive rather than a folder, because artifacts lose the executable bit).

**`desktop` job** (only if that platform's engine succeeded): unpacks the engine archive, sets
`STUDIO_PREBUILT_BIN` to it, runs `npm run package --workspace k7-standalone` (which compiles nothing
native) and `package-release.mjs --kind desktop`, and uploads the installer. Artifacts are uploaded
even when the run does not publish, so a side-branch dispatch can be downloaded and tested.

Nothing is signed: the macOS `.dmg` is unsigned and unnotarised, the Windows installer unsigned.

## OneDev

`.onedev-buildspec.yml` defines these jobs:

| Job | Trigger | Does |
|---|---|---|
| `lint and test` | Manual | In `node:24-alpine` with `git` and `ffmpeg`: `npm ci`, then in parallel and grouped with `concurrently`: `npm run lint`, `npm run lint:bytes`, `npm run typecheck -- --jobs 2`, `npm run test -- --jobs 4`. Red if any fails. The npm download cache is kept between runs. |
| `build studio images` | Run by `publish studio images` | Computes the build stamp, then builds and pushes `apps/k7/docker/Dockerfile` as `k7-webapp:<commit>` with the registry layer cache `cache:k7-webapp`. |
| `build engine image` | Run by `publish studio images` | Builds and pushes `engine/docker/Dockerfile` as `k7-runtime:<commit>` with layer cache `cache:k7-runtime`. A separate job with a three-hour timeout, because a cold build compiles Tracktion, JUCE and Faust. |
| `publish studio images` | Manual | Waits for the three jobs above to succeed, then retags both commit images as `:latest` and `:<stamp>` with `imagetools` (no rebuild, no pull). |
| `android` | Run by `release` | Same APK as GitHub's `android` job, in `node:24-trixie`, with caches for the SDK, Gradle, ccache, dependency sources and the debug signing key. Waits for `lint and test`. |
| `engine windows` | Run by `release` | On a Windows agent through a shell executor: initialises `commons` by hand, `npm ci`, `build-engine.mjs`, `package-release.mjs --kind engine`. Waits for `lint and test`. |
| `desktop windows` | Run by `release` | Unpacks the `engine windows` archive, sets `STUDIO_PREBUILT_BIN`, `npm run package --workspace k7-standalone`, `package-release.mjs --kind desktop`. |
| `release` | Manual | Gathers the Windows engine archive, the Windows installer and the APK into one build. |
| `check artifact upload size (probe)` | Manual | Publishes a zero-filled file (`PROBE_MB`, default 250) to test the server's upload limit before a real release. |

OneDev pushes its images to `dev.frediver.se/frediverse/k7/`; the deployment pulls GitHub's, from
`ghcr.io/fredericlb/`. The stamp and image tags are described in
[Images and deployment](./08-images-and-deployment.md).

## Reproducing CI locally

```bash
npm ci
npm run lint && npm run lint:bytes
npm run typecheck -- --jobs 2
npm run test -- --jobs 4
npm run build --workspace=apps/k7 --workspace=packages --if-present
(cd apps/k7/backend && npx tsc --noEmit)
(cd packages/rehearsal-server && npx tsc --noEmit)
```
