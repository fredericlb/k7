# Translation (paraglide)

k7's interface speaks English and French, through [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs). English is the base locale and the default.

## Where things are

| Path | Role |
|---|---|
| `apps/k7/frontend/project.inlang/settings.json` | The inlang project: base locale `en`, locales `en` and `fr`, message files at `messages/{locale}.json`. |
| `apps/k7/frontend/messages/en.json`, `apps/k7/frontend/messages/fr.json` | The two catalogues, one flat key per message (`"settings.menu": "Settings"`). Holes are written `{name}`. |
| a generated `paraglide` folder under the frontend's `src` | The compiled runtime and message functions; produced by the build and by `pretypecheck`, never committed. |
| `apps/k7/frontend/src/i18n.ts` | Binds the generated runtime to React: `LocaleProvider`, `useLocale()` (`locale`, `locales`, `setLocale`). |
| `apps/k7/frontend/src/i18nParts.tsx` | `parts()`: a translated sentence with React nodes in its holes, so a link inside a sentence keeps each language's word order. |
| `apps/k7/frontend/vite.config.ts` | Compiles the catalogues at dev and build time, and also compiles `packages/ui-rehearsal`'s own catalogue so both resolve the language the same way. |

Components import messages directly: `import { m } from "../paraglide/messages.js"` then `m["settings.menu"]()` or `m["conflicts.tab"]({ count })`.

## Choices

- **Strategy `localStorage`, then the base locale.** The language is a per-browser choice and the browser's `Accept-Language` is not read: a person picks a language once (`ui language`, the account tab, or the home Settings page) and gets it in that browser only.
- `LocaleProvider` is mounted above `AuthGate` in `appMain.tsx`; nothing that renders a message may sit above it.
- **Not translated**: command names (they are typed, so they stay English), the file syntax, and anything fetched from the file service, whose answers are English sentences. The command **descriptions** are translated, but they live in `packages/commands/commands.yaml` (`readable.en` / `readable.fr`) and in `LOCAL_READABLE` in `src/palette.ts`, not in the catalogues, because the server serves them.
- A person's own name for a command is stored per locale (`CommandPrefs.label`), since a rename is a sentence.
- A few strings are still literals in components (some panel titles, empty states); they are English or French in place. Moving them into the catalogues is open work.
- `@studio/ui-mini-player` and the other shared packages take every string as a prop, since each host translates through its own catalogue.

## Adding a message

1. Add the key to **both** `messages/en.json` and `messages/fr.json`, with the same holes.
2. Use it with `m["your.key"]({ hole })`.
3. Run `npm run test` in `apps/k7/frontend`: `src/messages.test.ts` fails when the catalogues name different keys, when a message's holes differ between languages, or when a message is empty. `npm run typecheck` regenerates the typed runtime first (`pretypecheck`), so a key that does not exist fails to compile.
