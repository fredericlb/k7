# Project archetypes

Every project is a `.k7` folder. What differs from one to another is what is written in it when it
is created, and above all which **surfaces** it declares. A surface is a view the project asks the
editor to draw. The editor draws the chains graph and the text editor for every project, and adds
the others only when the project declares them.

You pick an archetype when you create a project (see [Projects](./05-projects.md#creating-a-project)).
It is only a starting point: nothing in the project remembers it. You can add a surface later with
`project surface new <type>`, or delete a file from `surfaces/` to stop drawing that view.

| Archetype | Opens on | Surfaces it declares | Good for |
|---|---|---|---|
| `arrangement` | the timeline | `timeline` | writing and arranging a song |
| `mix` | the DJ desk | `turntables` | a DJ set from a playlist |
| `video` | the timeline, with the picture window | `timeline`, `viewport` | a song with picture, a music video |
| `live` | the chains graph | none | playing an instrument or voice through effects |
| `live-video` | the chains graph, with the picture window | `viewport` | the same, with a webcam |

## arrangement

"the timeline over the graph — one track, a synth, a pattern"

A minimal song that plays as soon as it is opened:

- **Tempo** 120, **time signature** 4/4, **sample rate** 48000 Hz.
- A **melody** lane holding a two-bar MIDI sequence (an ascending C major scale), played by its own
  copy of the built-in 4OSC synth.
- A group lane, **live**, holding two lanes generated by a Strudel pattern (`algo/pattern.strudel`):
  - **pad**, a sawtooth chord pattern played through its own 4OSC;
  - **kit**, a drum pattern (`bd hh sn hh`) played from samples.
- Both synths run into the mixer (`MIX`), which runs to the output (`OUT`). The run from `MIX` to
  `OUT` is the master chain: a module placed there processes the whole mix.
- Metronome off, and the default count-in before a recording.
- An empty `curves/` folder, ready for automation curves.

The 4OSC the lanes use is written once per workspace as a shared module (`@workspace/instruments/synth`),
so every project of the workspace uses the same one unless a lane overrides its parameters.

Every generated file carries comments that explain it. Opening the files in the editor is a good
way to learn the format.

**First steps:** open the project, press play, then edit `algo/pattern.strudel` and save to hear
the pattern change while it plays.

## mix

"two decks, a crossfade, and an empty set list"

A DJ set. It has no arrangement, no tempo and no time signature, only a sample rate. It declares a
`turntables` surface, `surfaces/desk.k7x`, drawn as the DJ desk pane.

- Two decks, **deckA** and **deckB**. Each deck is a channel strip: input trim, tempo, EQ (low, mid,
  high), filter, a headphone cue send, channel level, echo, and a fade. The two fades are the
  crossfader. Both decks meet at `MIX`, then `OUT`.
- Each deck can play a whole record or its four separated stems, each stem with its own control.
- `surfaces/desk.k7x` binds every control of the desk (crossfade, tempo, EQ, filter, cue, trim,
  level, echo, stems) to the module parameter it moves. Two lines are left commented:
  - `playlist:` names the set list the desk's browser shows. A new set has none, and the desk says
    so until you name one.
  - `stems: true` lets the desk separate a record you load unprepared.
- `mix.k7x` is the set's cue sheet: the desk writes your cue points there, song by song.

**First steps:** write a playlist in the workspace's `_playlists/`, name it in `surfaces/desk.k7x`,
then load songs onto the decks. The DJ section of this guide covers the desk in full.

## video

"the timeline and the viewport — the arrangement, plus a picture lane"

Everything the `arrangement` archetype writes, plus picture:

- `project.k7x` adds `viewport: [1280, 720, 30]` (the frame's width, height and frames per second;
  the fps is used by export) and `layers: [main]` (the draw order of the picture lanes).
- A sample video, `clips/sample.mp4`, copied into the project. Each frame shows its frame number, so
  a sync problem is easy to see.
- A picture lane, **main**, which places six seconds of that clip full-frame at the start. Picture
  lanes are timed in seconds, not in bars.
- Two picture outputs in the graph: `RENDER`, where every picture lane is composited, and
  `VIDEO_OUT`, the frame that leaves.
- A `viewport` surface, drawn as a floating window over the editor. `ui viewport` shows or hides it.

The picture section of this guide covers video lanes and the viewport.

## live

"no surface — an input, a fader, the output"

A rig you play through: something plugged into the audio interface, heard through this machine.
Nothing is arranged, and the project declares no surface, so it opens on the chains graph.

- **IN**, the live input. It names no channel yet, because which socket you are plugged into
  depends on your setup. Until you pick one, the project tells you the input feeds nothing. Pick the
  channel on the node's card, or write it in the node's file (`channel: [1]`, `channel: [1, 2]` for
  a stereo pair, or a channel label). Monitoring is on, so you hear the input without arming
  anything.
- **fader**, a channel strip (level in dB, pan, three EQ bands), at unity.
- **rec**, a recorder on the master run. Its round button starts and stops a take, without the
  transport. **Clear** drops the last take, **Save** sends it to the media library's recordings.
- The signal runs `IN` → `fader` → `MIX` → `rec` → `OUT`.
- Tempo 120 is kept for the metronome and for delays timed in beats. Metronome off.

**First steps:** pick the input channel on the IN node, then put an effect between `IN` and
`fader` to build an effects chain.

## live-video

"the same rig, plus a webcam and the viewport it fills"

The `live` rig, plus a camera:

- `viewport: [1280, 720, 30]` in `project.k7x`.
- **CAM**, the webcam. It names no camera, so it uses the machine's default one. Pick another on the
  node's card, by the camera's name.
- `CAM` runs into `RENDER`, so the camera fills the frame without any video lane.
- A `viewport` surface, the floating picture window. It is the only surface this archetype declares.

## What every archetype shares

- The folder ends in `.k7`, and the project's display name is the name you typed.
- The project uses the site's libraries (`@k7-core/…` and others), so a library must exist before it
  can open.
- The demo projects in the **Examples** workspace (a crossfade, a node graph, a rack, a synth and a
  video demo) show more worked examples (see
  [The home page](./03-home-page.md#the-examples-workspace)).
